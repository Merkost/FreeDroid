# Cleanup pass v5 — viewmodel-side bugs

Fifth refactor pass. Audited the SwiftUI view-models that had been mostly untouched. Two real concurrency / state bugs found.

## Bugs landed this pass

### FileBrowserViewModel.inspect race

A stale, in-flight inspector task could clear `inspectorIsPreparing` **after** a newer `inspect()` call had set it back to true:

```
inspect(A) → starts task A, sets inspectorIsPreparing = true
inspect(B) → cancels A, sets inspectorIsPreparing = true (new state)
task A's defer fires → inspectorIsPreparing = false (clobbers B)
```

The defer ran unconditionally. Fixed by replacing the `defer` with a positive completion path inside the task that re-checks `inspectedEntry?.path == targetPath` before mutating state. Cancelled or stale tasks now exit silently.

Also dropped 4 redundant `await MainActor.run { ... }` calls inside the task — the class is `@MainActor` so the Task already inherits the actor.

### GalleryViewModel.loadMore duplicates on exhausted feed

`loadMore` didn't gate on `hasMore`. After the feed was exhausted:

```
let page = try await loadMediaUseCase(folder:, page: nextPage)
...
nextPage = page.nextPage ?? nextPage  // stays at last page when nextPage is nil
```

Subsequent `loadMore()` calls (which happen via infinite-scroll plumbing whenever the user scrolls within the bottom range) re-fetched the same final page. `rawItems` accumulated duplicates → duplicate cells in the masonry grid → wasted bridge IPC + thumbnail decode.

Fix: `guard hasMore || rawItems.isEmpty else { return }`. Also reset `hasMore = true` at the start of `load()` so the first page after a folder switch isn't gated.

## Cleanup

- Extracted `recordError(_:)` helper in both FileBrowserViewModel (4 call sites) and GalleryViewModel (1 call site) replacing the dual `catch as TransportError / catch` arms.
- Improved `AppContainer.fatalError` message to make clear it's a build-packaging failure (missing bundled adb resource) and not a runtime user error — points the future-self / contributor at xcodegen + clean rebuild as the fix.

## Bugs looked at and judged not worth fixing this pass

- `FileBrowserViewModel.activateFocused` for a file just toggles selection. UX-wise it should probably trigger Quick Look. Polish task.
- `FileBrowserViewModel.extendFocus` defaults `currentIndex = 0` when no focus exists; extending from nothing would select 0..target. Surprising but rare.
- `XPCFileServerHandler` (main app) duplicates the bridge's IPC dispatch shape but differs in transport-acquisition logic. Real dedup needs the A1 type-safe IPC refactor first.

New items surfaced this pass:

- **`FileBrowserViewModel.inspect` should de-dup concurrent same-path triggers** rather than cancel-and-restart. Currently SwiftUI selection changes can fire `inspect()` rapidly during arrow-key navigation; each one starts a fresh download even if the previous would have succeeded.
- **Gallery infinite-scroll trigger should track "in-flight page N" identity** to avoid even the still-correct loadMore loop firing while a page is in flight. Cheap once hasMore gating is in place.
- **`recordError` is the same shape in two view models.** Could promote to a `TransportError.from(_ error: Error)` static helper in FreeDroidDomain.
