# Cleanup pass v3 — and forward plan

> Third refactor sweep. Different files this time — went into the ones I hadn't audited carefully before.

## Bugs landed this pass

### `DeviceRegistry.rescan` recreated sessions every 15s (perf regression)

The periodic 15s rescan called `ADBSession.init` for every connected device on every pass, dropping the cached `info`, the cached `host-features` set, the cached zstd flag, and the **entire warm `ADBSyncConnectionPool`**. Wire-client benefits ate themselves alive on a 15-second cycle.

Fix: `reuseOrCreateADBSession(deviceID:serial:)` / `reuseOrCreateMTPSession(deviceID:raw:)` look up the existing transport for the same `DeviceID` and hand it back if present. Only newly-discovered serials get a fresh session. Cached state and the warm pool persist across rescans.

### `LiveADBRunner.run` didn't honor Task cancellation

A `Task.cancel()` on a long `adb pull` left the subprocess running until adb finished naturally or the 600s timeout fired. Now wrapped in `withTaskCancellationHandler { ... } onCancel: { processBox.terminate() }` where `ProcessBox` holds the `Process` behind an `OSAllocatedUnfairLock`-protected `Holder` struct (Process isn't Sendable). Real cancellation actually terminates the subprocess.

Bonus: `run` and `runWithStdin` were ~50-line near-duplicates. Collapsed into one `runProcess(command:stdin:timeout:)` taking an optional stdin payload. Net -75 lines.

### `FreeDroidProviderExtension` mutations didn't invalidate the appex's `EnumerationCache`

`EnumerationCache` holds folder listings for 5 minutes. `createItem`, `modifyItem`, `deleteItem` would succeed against the device but the appex's local cache stayed stale — so newly uploaded files wouldn't show in Finder for up to 5 minutes, deleted files would linger, renamed files would appear under both names. (The bridge already invalidated its own 5s listing cache; the appex's longer-TTL cache had diverged.)

Fix: new `invalidateAndSignal(parent:)` evicts the parent listing from `EnumerationCache` and calls `NSFileProviderManager.signalEnumerator` so Finder re-walks. Called from all three mutation paths.

## Bug-shaped things looked at and judged not worth a fix this pass

- **`WifiADBCoordinator`** does substring checks for "failed"/"error" in adb output to decide whether to throw. Fragile, but adb's actual output is reliably one of those strings; replacing with regex+exit-code checks is a polish task.
- **Bridge `listCache` vs appex `EnumerationCache`** TTL mismatch (5s vs 300s). After the mutation-invalidation fix above, the only remaining divergence is for **external** changes to the device (a user moving a file via their phone's Files app). That's a "phone-side change isn't reflected in Finder until Finder explicitly re-enumerates" problem with no clean fix without a phone-side watcher. Document, defer.
- **Transport-kind switch leaks old session** (rare: device changes between ADB and MTP modes between rescans). Identity-tracking refactor would address it cleanly. Not urgent — happens rarely and the orphaned actor gets GC'd eventually.

## Forward plan (still relevant from v2 + new entries)

### Highest-leverage / shippable

1. **F1 — In-app live transfer panel for Finder copies.** Appex writes JSONL events to its container's Caches dir; main app (non-sandboxed) watches via `DispatchSource.makeFileSystemObjectSource`. Half-day. Biggest perceived-quality jump.
2. **F2 — Cross-device drag-and-drop.** With wire-client fetch/upload + the pool, the orchestration is mostly a `CrossDeviceCopyService` actor coordinating two `TransferJob`s. ~1 day.
3. **F3 — Folder paste / drag from Mac → phone.** Today Finder does per-item enumeration; fine. Adding our own progress-tracked batch upload (with explicit folder structure preservation, EXIF preservation toggle, optional MediaStore rescan deferral) would be a real differentiator.
4. **F4 — Resume on cancel.** `RECV`/`SEND` with offset support for >1GB files that survive USB hiccups.

### UI polish that lands fast

5. Active-transfer count badge on menu bar icon (e.g. "iphone.gen3" + a small "3" overlay when 3 transfers in flight).
6. Device-card per-card transfer progress bar (right now `transferFraction` exists but isn't surfaced uniformly).
7. Recently-used remote folders dropdown when uploading.
8. Confirmation dialog with file count + total size before deleting more than 10 files.

### Architecture cleanup

9. **A1 — Type-safe IPC.** Replace `IPCRequest` enum + handler switch with `XPCFileServerProtocol` methods. Half-day mechanical refactor; large diff that genuinely needs rebuild validation between steps.
10. **MTPSession audit.** Haven't deeply reviewed it; it likely has similar issues to what `ADBSession` had (session-recreate on rescan, error-propagation). Now that the registry reuses MTP sessions across rescans, this is less urgent but worth a pass.
11. **Bridge `listCache` eviction-on-external-mutation.** Wire client could subscribe to inotify or a 1-second poll on hot paths. Speculative.

### Distribution

12. **D1/D2** Notarized signed release flow + tag-triggered DMG via Actions. Needs `SIGNING_CERT_P12` + Apple ID credentials wired into repo secrets. Outside what this session can configure.
13. **Sparkle live appcast.** Wired in `Package.swift`; needs appcast.xml hosting.
